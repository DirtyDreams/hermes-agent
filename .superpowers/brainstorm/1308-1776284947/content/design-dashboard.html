Design — Section 5: Track B — Agent Dashboard

Skills browser, MCP tools, presets, batch jobs, health

Backend Endpoints

  • GET /api/skills/list — lists all installed Hermes skills (reads from ~/.hermes/skills/)
  • GET /api/mcp/tools — lists connected MCP servers and their available tools
  • GET /api/providers/list — lists available providers/models from Hermes config
  • GET /api/system/health — enhanced: adds memory usage, Hermes uptime, active model
  • GET /api/jobs/list — lists scheduled/active batch jobs from Hermes
  • POST /api/jobs/cancel/:id — cancels a running or scheduled job

Skills Browser Panel

  • Trigger: "Skills" tab in the dashboard overlay
  • Skill card: name, description, trigger phrase (if any), source (built-in / user / marketplace)
  • Search/filter: text search across name + description, filter by source tag
  • Skill detail: click card to expand — shows full description, instructions, example prompts
  • Enable/disable: toggle to add/remove skill from active configuration

MCP Tools Panel

  • Server list: each connected MCP server as a collapsible section
  • Per-server tools: nested list of tool names + brief descriptions
  • Tool invocation: click a tool to see its schema (input parameters) — read-only
  • Status badge: connected / error / connecting per server

Provider / Model Presets

  • Preset cards: visually distinct cards for each configured provider/model combo
  • Quick activate: click a preset card to immediately apply it (updates settings, restarts session if needed)
  • Preset editor: "Edit" button on each card opens a modal to modify provider, model, toolsets, custom flags
  • Add new: "+ Add Preset" card at the end
  • Current app already has 3 presets (local, openrouter, codex) — these become visual preset cards

System Health & Batch Jobs

  • System health: memory usage bar, Hermes uptime, active model name, Hermes version, config path — all in one compact status card
  • Batch jobs: list of scheduled/running jobs with: job ID, trigger type (cron / manual), status (scheduled / running / done / failed), next run time
  • Job cancel: cancel button per job

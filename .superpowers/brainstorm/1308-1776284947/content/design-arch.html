Design — Section 1: Overall Architecture

High-level system structure

The app has two main tracks running in parallel, sharing a common React component library:

Track A — Chat Infrastructure

  • Real-time token streaming via SSE (Server-Sent Events)
  • Backend spawns hermes chat with streaming output parsed token-by-token
  • Tool Activity side panel (WebSocket or polling for live tool events)
  • New chat message components with token-by-token rendering
  • Message state machine: idle → sending → streaming → complete | error

Track B — Agent Dashboard

  • Read-only API-driven panels: skills, MCP tools, system health
  • Hermes CLI commands: hermes skills list, hermes tools list, hermes system info
  • Provider/model preset management via config file editing (reuse existing /api/config/*)
  • Batch job status via hermes jobs list

Frontend Shared Layer

  • Layout context — collapsible sidebar state, active panel (chat/dashboard), overlay open/close state
  • HermesAPI client — typed fetch wrapper for all /api/* calls including new SSE endpoint
  • Component library — existing UI primitives in src/components/ui/ extended with new ones

Backend Changes

  • New: SSE endpoint — POST /api/chat/stream — spawns hermes and streams tokens back as SSE events
  • New: Tool events — GET /api/chat/tool-events — SSE stream of tool calls and their status
  • New: Skills/Tools — GET /api/skills/list, GET /api/tools/list, GET /api/system/health, GET /api/jobs/list
  • Existing endpoints preserved — health, config read/write, sessions list, chat send (fallback)

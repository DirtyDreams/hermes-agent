Design — Section 4: Track C — Workspace File Browser

Full file explorer with git detection and preview

Backend Endpoints

  • GET /api/workspace/tree — returns directory tree starting from Hermes working directory
  • GET /api/workspace/read?path= — returns file content (text, code) or image as base64
  • PUT /api/workspace/write — create or overwrite file at given path
  • DELETE /api/workspace/delete?path= — delete file or directory
  • POST /api/workspace/mkdir — create directory
  • GET /api/workspace/git — returns git branch name and dirty file count

File Browser Panel (Overlay)

  • Trigger: "Files" icon button in the chat header — opens as right-side overlay panel
  • Header: current directory breadcrumb (clickable segments), git branch + dirty indicator
  • Directory tree: collapsible tree view, lazy-loaded on expand, folders/files have distinct icons
  • Context menu: right-click (or long-press) on any item: New File, New Folder, Rename, Delete
  • Search: filter files by name within current tree

File Preview

  • Click a file: preview panel slides in from the right (or takes the main area on mobile)
  • Text/code files: syntax-highlighted via a lightweight highlighter (Prism or highlight.js)
  • Markdown: rendered preview
  • Images: displayed inline with actual dimensions
  • Edit mode: "Edit" button switches to textarea; "Save" calls PUT /api/workspace/write
  • Large files: truncated at 500 lines with "Load more" or "Download" option

Git Detection

  • Calls GET /api/workspace/git on panel open and on file change
  • Shows branch name badge (e.g., "main") + orange dot if dirty (uncommitted changes)
  • No git operations (commit, push) — read-only detection only

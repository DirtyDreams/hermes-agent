Design — Section 2: Track A — Core Chat Enhancement

Streaming, tool panel, message lifecycle

Backend: Streaming Endpoint

POST /api/chat/stream

  • Accepts same payload as /api/chat/send
  • Spawns hermes chat child process with output piped to a parser
  • Emits SSE events: token, tool_call, tool_result, done, error
  • Streams tokens immediately as they're emitted — no buffering
  • Timeout handling: kills process after timeoutMs, emits error event

Frontend: Streaming Message Component

  • Message state: idle | streaming | complete | error
  • Token rendering: each token appends to content via useRef on the pre element — no re-renders per token
  • Typing indicator: shows "..." or animated dots while waiting for first token
  • Tool calls: detected from tool_call SSE events, passed up to Tool Activity panel
  • Regenerate: re-sends the user message, replaces the assistant's incomplete message in-place
  • Cancel: aborts the in-flight request, marks message as error with "Cancelled"

Tool Activity Side Panel

  • Trigger: opens as an overlay/drawer from the right edge when first tool call fires
  • Tool card: shows tool name, params (collapsible), status badge: running | done | error
  • Result preview: collapsible accordion showing truncated result
  • Auto-close: collapses when all tool calls in a turn are complete
  • Collapsed state: small pulsing indicator on right edge when tools are running

Message Editing

  • Click on any user or assistant message to "branch" — creates a copy in the composer that can be edited and re-sent
  • Re-send from a branched message creates a new turn, doesn't destroy subsequent history
